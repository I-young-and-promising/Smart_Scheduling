# 智能排班系统 PRD

## 1. 产品概述
智能排班系统是一款面向客服/零售等轮班场景的管理工具，帮助排班管理员（Admin/HR）高效生成、调整、发布员工班表，同时为员工提供「我的班表」自助查看与排休申请能力。

## 2. 目标用户
- **排班管理员 / HR**：负责月度排班生成、合规检查、异常调整、发布与导出。
- **普通员工**：查看已发布班表、提交排休申请。

## 3. 核心功能模块

### 3.1 排班工作台（首页 `/`）
- 月历聚合视图：展示每日各班次人数、夜班人数、周末/节假日高亮。
- 合规警告面板：列出当日或当月违规项，点击可定位到具体日期/员工。
- 快捷操作：一键 AI 生成排班、导入历史班表、导出 Excel、发布班表、查看变更日志。
- 发布状态栏：显示当前月份是 draft 还是 published。

### 3.2 矩阵视图（`/schedule/matrix`）
- 员工 × 日期甘特图，每个单元格展示班次色块。
- 支持点击单元格修改班次、撤销修改。
- 管理员可在此触发 AI 重新生成当前月份排班。
- 违规单元格用红色边框/图标标识。

### 3.3 员工管理（`/employees`）
- 员工列表：姓名、工号、部门、状态、效率标签、能力标签等。
- 新增/编辑员工弹窗，维护员工基础信息、偏好、可排班次、 mentor 关系等。
- 员工数据默认存储于飞书多维表，支持 `DATA_SOURCE_DRIVER` 回退到 PostgreSQL。

### 3.4 班次配置（`/shift-configs`）
- 班次列表：早班(day)/中班(middle)/晚班(night)/休息(rest) 的时间、人数上下限、节假日上下限。
- 规则配置卡片：夜班上限、周工作天数、连续休息/白班上限、夜班后强制休息天数、新员工带教同步、高低效率搭配、工时结余动态调节等。

### 3.5 节假日管理（`/holidays`）
- 节假日日历：标记法定节假日、调休日、必须工作日。
- 设置节假日对应的最小/最大班次人数。

### 3.6 排休申请（`/leave-requests`）
- 员工提交本人请假/调休申请。
- 管理员审批列表：按状态筛选、一键通过/驳回。
- 审批通过后，对应日期自动在班表中标记为休假。

### 3.7 我的班表（`/my-schedule`）
- 员工端仅查看已发布班表。
- 未发布或没有班表时展示空态提示。
- 按月份切换、展示每日班次与工时统计。

### 3.8 AI 排班引擎
- 基于贪心构造 + 随机重启 + 12 秒超时预算求解。
- 支持三种策略方案对比：均衡(balanced)、偏好优先(preference)、公平优先(fair)。
- 优化模式：基于现有班表做最小改动重排。
- 合规校验引擎校验班次衔接、夜班上限、连续休息、周工作天数、节假日人数、新员工带教同步、高低效率搭配、工时结余等规则。

## 4. 页面结构
| 路由 | 页面 | 可见角色 | 说明 |
|------|------|----------|------|
| `/` | 排班工作台 | admin | 月历+统计+警告+发布 |
| `/schedule/matrix` | 矩阵视图 | admin | 甘特图单元格编辑 |
| `/employees` | 员工管理 | admin | 员工 CRUD |
| `/shift-configs` | 班次与规则配置 | admin | 班次+规则配置 |
| `/holidays` | 节假日管理 | admin | 节假日维护 |
| `/leave-requests` | 排休申请 | all | 员工提交、管理员审批 |
| `/my-schedule` | 我的班表 | employee | 查看已发布班表 |
| `*` | 404 | all | 未匹配路由 |

## 5. 角色与权限
- **admin**：所有已登录用户统一视为 admin，可访问管理端全部页面和接口，可操作生成/编辑/发布/导入/导出/审批。
- **employee**：未登录访客兜底，仅可查看本人班表（需发布后）和提交本人排休。
- 未匹配花名册的登录用户落到演示员工「张伟（001）」档案，便于分享体验。

## 6. 关键业务流程

### 6.1 月度排班生成与发布
1. 管理员进入排班工作台或矩阵视图。
2. 选择月份，点击「一键 AI 排班」。
3. 系统调用求解引擎生成合规班表；管理员可切换 balanced/preference/fair 方案后应用。
4. 管理员可手动点击单元格调整班次；系统自动生成变更日志与合规警告。
5. 确认无误后点击「发布」，员工端「我的班表」即时可见。

### 6.2 历史班表导入
1. 管理员在工作台点击「导入历史班表」，上传 Excel。
2. 前端解析 Excel 后按工号+日期提交到后端。
3. 后端写入排班结果（source=imported），并记录导入历史。
4. 管理员可在导入历史中查看/删除某次导入。

### 6.3 排休审批
1. 员工在「排休申请」页选择日期范围、填写原因并提交。
2. 管理员在列表中看到 pending 申请，选择通过或驳回。
3. 通过后，对应日期员工班表标记为 leave。

## 7. 数据实体
- **Employee**：员工基础信息、偏好、可排班次、能力/效率标签、mentor 关系、工时结余。
- **ShiftConfig**：班次代码、名称、时段、人数上下限、节假日上下限。
- **ScheduleEntry**：某员工某日的班次记录，source 区分 generated/manual/imported。
- **SchedulePublish**：月份发布状态（draft/published）。
- **ScheduleChangeLog**：班次变更记录（谁在何时把某员工某日班次从 X 改为 Y）。
- **ScheduleImportHistory**：导入历史（月份、文件名、员工数、记录数、状态）。
- **LeaveRequest**：排休申请记录及审批状态。
- **Holiday**：节假日日期、类型、是否必须工作、权重。
- **RuleConfig**：JSON 形式的排班规则配置。

## 8. 非功能需求
- **数据源双模式**：通过环境变量 `DATA_SOURCE_DRIVER` 在飞书多维表（bitable）与 PostgreSQL（postgres）之间切换。
- **响应式**：管理端在桌面端使用，员工端支持移动端查看。
- **性能**：AI 求解 12 秒超时；Bitable 全量拉取分页 500 条。
- **可观测性**：所有 Bitable 调用记录耗时与失败日志；后端接口记录 trace。

## 9. 验收标准
- [ ] 管理员可在工作台一键生成某月排班，生成后月历展示每日班次分布。
- [ ] 矩阵视图支持点击单元格修改班次，修改后同日期同员工不产生重复记录。
- [ ] 合规警告能正确显示夜班超限、连续休息超限、节假日人数不足等异常。
- [ ] 导出 Excel 能正常下载并包含所选月份全部员工班表。
- [ ] 发布后员工在「我的班表」能看到对应月份班表；未发布时不展示。
- [ ] 排休申请通过后，对应员工对应日期班表标记为休假。
- [ ] `DATA_SOURCE_DRIVER=postgres` 时系统能正常回退到 PostgreSQL 运行。
